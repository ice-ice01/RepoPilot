
# Agent 工作流

用户消息进入 `/api/chat` 后：

1. `ChatAgent` 使用原生工具调用能力选择下一步要使用的工具。
2. 工作区工具可以列出文件、读取文件以及搜索本地代码。
3. 记忆工具用于检索当前范围内的对话历史。RAG 用于检索可复用的非结构化证据，例如 Issue 描述、PR 讨论、失败的 CI 日志、项目文档、用户上传的知识以及经过确认的记忆笔记。工作区工具和结构化工具则负责处理当前代码与实时事实。
4. 专项 Agent 分别执行 Issue、PR、CI、报告或安全分析。
5. `SafetyAgent` 负责处理对外写入意图。在 MVP 阶段，它只生成操作草稿，不会直接写回 GitHub。
6. 后端记录工具调用、引用来源、最终回答以及持久化的聊天记忆。

对于涉及多个领域的工程决策，`ChatAgent` 可以调用 `workflow.run_engineering_review`：

1. `PlannerAgent` 默认调用项目配置的模型，语义理解用户目标并选择任务、目标与依赖。程序固定 Agent 身份、目标 ID、证据访问范围、验收标准与安全门，校验任务可用性、重复任务、缺失依赖和环。校验通过后创建 `WorkflowSpec`。
2. `WorkflowOrchestrator` 在依赖条件满足时，并行执行已经就绪的任务。
3. 现有的 Issue、PR、CI、RAG、仓库健康检查和安全能力会作为工作流任务执行。
4. `ObserverAgent` 检查任务输出中的合并门禁、跨 Agent 冲突、低置信度、证据缺失以及需要人工确认的事项。
5. `SynthesisAgent` 生成一份统一的决策备忘录，后端同时持久化 `AgentWorkflowRun` 和 `AgentTaskRun` 记录，以便后续追踪和审查。

Planner 的模型输入只包含用户目标、可用/必选任务，以及已同步 Issue、PR、CI 的简短事实摘要；不发送完整代码、日志、文档正文、密钥或全部聊天上下文。知识检索能力的可用性与“强制加入检索”分别表达，避免把未强制检索误认为禁止检索。

无密钥、模型调用失败、总耗时超限、JSON 或任务图校验失败时，使用独立的 `RulePlannerAgent` 兜底。默认总调用预算为 30 秒（`PLANNER_TIMEOUT_SECONDS`），输出上限为 2048 token（`PLANNER_MAX_TOKENS`），不自动重试。原有专用 Agent 的模型调用行为保持不变。规则回退不能纠正所有结构合法的语义误判，Observer 和人工审核仍然必要。

重规划同样优先调用模型，输入已有任务、执行结果和 Observer 反馈。当前执行器复用成功结果，因此仅允许补充任务；已有任务的 ID、目标、权限、目标描述和依赖保持冻结，不允许模型把任务转向新同步的对象。安全门及人工确认要求只能增加，不能取消；缺失安全检查会由程序补回。

每次规划在 `WorkflowSpec.planning_trace` 记录模型/规则回退模式、阶段、固定错误码、耗时和程序补入的必选任务，随计划及执行记录保留。异常详情、供应商响应和密钥不写入 trace；请求取消会正常传播，不启动回退。

历史 A/B 实验继续明确使用独立规则规划器作为基线，其原始结果和旧模型原型保留；它们不等同于本次正式实现的回归成绩。
