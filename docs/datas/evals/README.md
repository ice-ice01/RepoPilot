# 固定问答评测集

`wardrobe_rag_cases.json` 是 14 题 wardrobeAgent 技术问答基准，来源是本项目已上传的 `AI-Agent-工具调用与穿搭生成流程.md`。原文副本位于 `../sources/`，SHA-256 为 `1ab2a72fcde71f60e353aaa2988093e26634f9c7d7e10635454eef58ac54a7d5`。用例由本次修复依据该资料编写和核对，**不冒称已经过独立人工审核**；正式发布前应由维护者复核事实、范围和验收条件。

只适用于 `ice-ice01/wardrobeAgent`。先在该仓库知识库导入或保留同名原文并完成索引，再在 `/evals` 选择“wardrobeAgent：工具调用与穿搭生成固定基准”。不要把题目 JSON 或参考答案导入知识库，以免答案泄漏。源文档变化后应重新复核用例并版本化，不能只为提高分数修改参考答案。

Schema v3 每题包含：`question`（实际给 ChatAgent 的问题）、`reference`（语义事实要点）、`reference_outcome`（Agent Goal 的任务验收要求）、`source_file`（该仓库中应已入库的来源），以及可选的硬规则。参考答案和验收要求仅提供给评分器，不注入 ChatAgent。允许同义表达、不同排版和有证据支持的合理补充；对文档未说明的生产配置，要求明确说明资料不足。`must_include`、`must_not_include` 是字面字符串规则，只在确实要求固定表达时使用，不替代语义事实审核。

后台仅按所选仓库解析来源 ID，不借用其他用户或仓库资料。来源文件名检查只证明同名文档已入库，并不自动保证内容版本相同；`source_checksums` 是维护者核对源文档版本的依据。

自动文档冒烟测试仅检查运行链路。它的参考内容是文档摘录，不能用作固定回归或发布基线。严格对比要求相同非空评测集 Hash、仓库、Judge、Ragas、Top-K 及评分口径版本；旧评测的异常重评分保持原问题、答案、证据和验收条件，不会自动变为新版本基线。

Judge 单次请求预算仍使用 `RAGAS_TIMEOUT_SECONDS`（默认 120 秒）；完整多步指标使用 `RAGAS_METRIC_TIMEOUT_SECONDS`（默认 360 秒）。`RAGAS_METRIC_CONCURRENCY` 默认 2，控制同时运行的指标数，排队时间不计入指标预算。超时或缺失指标保留为错误；仅重试错误指标，禁止用 0 或 1 代替失败。部分均值显示已评分数量，不作为完整质量判定。

保存的检索分数仍覆盖全部观察轮次，不删除早期差结果；逐题“各轮检索来源诊断”另外列出预检索和每次工具检索的查询、证据数量及来源命中，便于判断后续检索是否补救。此诊断不额外调用 Judge，也不宣称知道模型内部究竟采用了哪段证据。
